# Changelog

## 1.0.0 (2026-10-12)

First public release. It shops like a real customer: browses, picks options, adds to cart, opens the cart, and stops before checkout. It never enters checkout, never pays, never logs in, and only types fake test text, plus discount codes your store shows on its own pages. Like any shopper, the store's analytics will see the visit and the add to cart. The Checkout button is found, never tapped, and the test cart is left as it is. `--no-cart` browses only.

- Persona interview, persona card and validator.
- Shopify Online Store themes only. The runner reads the store's home page before the browser starts and exits 2 for any other platform or a headless (Hydrogen) storefront; when the home page cannot be read, the first page must set `Shopify.theme`, or the run stops with exit 2.
- The panel's writes are a strict allow-list: only own-host Shopify cart operations (`/cart/add`, `/cart/change`, `/cart/update`, `/cart/prepare_shipping_rates.json`) with a clean path, no routing headers, a parseable body and no checkout or redirect key are sent; every other write, GraphQL and `/api/` included, is stopped and makes a later quit a tool limit. Checkout, account, password and cart-permalink reads are stopped too.
- Playwright runner on Chromium only: iPhone 14 (iPhone screen, touch and user agent on the Chrome engine) and Pixel 7, with per-persona network speeds. Safari-only bugs are not caught.
- Checkout guard: every checkout request and every redirect hop toward a checkout is stopped, and the run measures that no checkout page loaded. Cart writes the page itself makes are stopped when the panel recognises them.
- Tracker and third-party blocking with an allow-list, and a report of allowed and blocked hosts.
- Labelled test arrivals (`utm_source=shopper-panel`), no referer.
- `--i-own` must match `--url`.
- Product page detection, structured price reading, lazy content loading, pop-up closing, sold-out skipping, bot-check detection.
- Offline made-up store, `npm test` and `npm run demo`.
- Checkout guard covers non-English checkout addresses (by page content), new tabs and frames, buy-now redirects, the WooCommerce Store API checkout, `checkout.php`, `finishorder.php` and embedded checkouts.
- A journey error exits 1 with run status INCOMPLETE.
- A myshopify owner is accepted for a custom domain only when the store confirms it.
- Prices in more currencies (Rs., R, ₱, ฿, ₫, RM, Kč and others); a price the panel cannot parse but the page data confirms is labelled as shown in an unrecognised format.
- Report text escapes Markdown links, images and emphasis, and neutralises bare links, `www.` links and e-mail links.
- Background prefetch and prerender are blocked in three layers (page script, page and header stripping, refused prefetch requests, plus Chromium launch flags).
- A redirect after an add to cart, buy-now or form POST to a page of no known kind is stopped without requesting it; each hop is recorded with its real method; a content check is reported as "reached the store's server but was not shown".
- A page the panel cannot read (no recognised heading, product grid, form or button) is a tool limit: run status INCOMPLETE and exit 1, never a shopper quit. Headings may be h1, h2, role=heading, the product title or the product name from the page data. WooCommerce block-theme product grids are recognised.
- Page text is stripped of control characters before it is printed in the terminal.
- Beacons, `fetchLater` and keepalive requests (which Chromium sends past the page's request routing, even as a page closes) are dropped by a page script in every frame it reaches and, on Chromium, by a browser-level request guard that only sees what got past the routing and counts each stop in the normal blocked and checkout totals; service worker registration is refused; dropped reports are counted.
- Named block rules are now host rules (host name only, at a label boundary) or path rules (whole path segments or query parameters, with `own_host`), checked by `npm run validate`. Own-host path rules start at the platform's real roots or require a query string, and never apply under the store's catalog paths (`/products/`, `/collections/`, `/product/`, `/product-category/`, `/shop/`, also with a locale prefix). Named rules never stop documents; own-host and allowed-host images, style sheets and fonts are only stopped by host rules and root-anchored platform endpoint rules. A product handle, collection or file name with a tracker word in it is no longer blocked. A journey that fails after any other named-rule stop on an own-host or allowed-host request is a tool limit naming the rule.
- A first-party Google tag served from the store's own host (`.../gtag/js?id=G-...`, `.../gtm.js?id=GTM-...`, `.../g/collect?v=2`) is blocked by query shape. Other first-party tag proxies may not be, and the report says so.
- Block rules can be marked `"endpoint": true` (host rules; path rules whose alternatives all start at the site root, optionally after a locale prefix, with a literal first path segment; or path rules whose alternatives all need a query string that is not optional and a `name=` parameter; and in every case the pattern must not match ordinary theme, app, extension, product or home paths; an endpoint host rule covering the store's own or an allowed host stops the run) or carry `"endpoint_hosts"` (a looser third-party path rule, an endpoint on those hosts only). The platform analytics rules, the platform's tracker scripts on `cdn.shopify.com` and the first-party Google tag rule are endpoints, and their stops never turn a journey into a tool limit. After any other named-rule stop on the store's own or an allowed host, only a quit a missing request could cause (an error or a page that did not load, a page not usable in time on arrival or after tapping a product, an element not found, a page the panel could not read) becomes a tool limit naming the rule; content quits (required information missing, sold out, the price past the persona's screens, a price element with no amount, the persona's tap limit, a covered button) keep their kind with a caveat naming the rule.
- The own-host Shopify monorail, `/api/collect`, perf-kit, trekkie, `wpm@`, `cdn/wpm/` and web pixels roots are also matched after a locale prefix such as `/en-gb/`, `/zh-hant/` or `/es-419/`; the catalog exemption accepts the same prefixes.
- Triple Whale's pixel script on `cdn.shopify.com` and the help desk and review app event rules are endpoints. At start, an allowed host that a named host rule still blocks prints a warning (also in the report and result.json `setup_warnings`).
- A content quit after a named-rule stop is marked "[a block rule may have affected this]" in the report table, and the summary counts the blocking findings that came after such a stop.
- The report's Safety section says whether the Chromium browser-level request guard attached.
- Errors the test browser itself causes (service workers turned off, including in sandboxed frames) are set aside as "service worker unavailable in this frame (test browser blocks service workers)", never reported as the store's script errors.
- A product page with no price the panel recognises and no structured price is a tool limit; a structured price whose digits are not shown stays missing store information.
- The `.gitignore` step adds each entry on its own line, guards a missing final newline, and checks the result with `git check-ignore`.
- `"endpoint"` and `"endpoint_hosts"` are honoured on the shipped block rules only; a user rule that sets either is refused at start (exit 2) with the fix. No named rule can stop the store's own cart and store API calls (`/cart`, `/cart.js`, `/cart/add`, `/cart/change`, `/cart/update`, `/cart/clear`, `/api/<version>/graphql.json`, `/wp-json/wc/store/...`). Validator errors now suggest the fix. `docs/block-rules.md` has worked examples.
- A journey watchdog caps each journey at the shopper's patience budget plus 3 minutes; a page that stops responding becomes a test error and the run still writes its report and result.json. The panel's own in-page requests give up after 10 seconds.
- The home page check and the catalog exemption take a real locale prefix only, so `/pay/`, `/buy/`, `/faq/`, `/cdn/` and `/app/` are not treated as locales.
- A store that does not answer shows "Error (not a shopper result)" with a plain message, and is never listed under Blocking.
- `npm run fixture` prints the practice store's port, pages and the exact command; `--i-own localhost` matches `127.0.0.1` on this computer.
- The report: a "What to fix first" section ranked by how many shoppers each problem stopped; test problems listed apart from shopper results; a bare heading is "heading only", not found; "1 screen" in the singular; lighter Markdown escaping; a note that blocking localhost on a practice run is intentional.
- `-h` prints the help; `npm run validate` checks `./personas` only and labels each path; the dry run lists each rule once.
- A locale is two letters, optionally with a region of two letters, four letters or three digits (`en-us`, `zh-hant`, `es-419`), so `/pay-now/`, `/buy-now/` and `/one-tap/` are never taken for a locale.
- A spec list or table term (`dt`, `th`) followed by its `dd` or `td` counts as found whatever the length; a fieldset legend counts its option labels; a Dawn accordion title uses its `<details>` content, with the next segments as the fallback; a heading-only hit on one pattern no longer stops the later patterns.
- "What to fix first" groups by the exact missing need or reason, and lists only journeys whose own quit was blocking. Tool limits and bot checks read "Test limit (not a shopper result)" and are left out of the stopped-short list.
- A page load that timed out on a server that took the connection says "the page did not load"; a refused connection says "refused the connection"; a store that does not load reads "could not start". When every journey was a test error the summary says no journey could be tested.
- Ctrl-C and the watchdog cut the journey's browser off from the network before closing, and Ctrl-C writes a partial report. The final browser close has a timeout.
- The practice command runs from the project folder; the "No persona files" message says how to point at it and never suggests copying the examples. With no arguments the runner says "Missing --url and --i-own." first.
- The validator reads the config next to the persona folder when there is none in the current folder, shows `(no name)` for a rule without a name, and a host written as a URL gets a fix. `docs/block-rules.md` says when a rule is still needed and anchors example 3; the report's "Tested:" address is not escaped, and the loopback note shows only when localhost was blocked.
- Adding to cart is the default; `--no-cart` browses only, `--cart` is accepted and changes nothing, and the two together are refused. Every on/off option refuses a value (`--cart=false` is an error), unknown options and stray words are errors, and `--pause` must be a number.
- Fixed typing only: `TEST` (or `ABC`) in a required personalisation box, one public postcode in the shipping estimator, and up to 3 discount codes the store shows on its own pages. A persona `type_text` is refused by the validator; the report lists exactly what was typed.
- Private network and cloud metadata addresses are refused as `--url`. The myshopify ownership check looks the address up first, refuses a private answer, and does not follow redirects.
- Persona and config files: a leading byte order mark is ignored, files over 256 KB are refused, the `id` must match the file name, and two files with the same `id` are an error. Patterns that could run very slowly are refused.
- The `{price}` pattern matches a price in any currency. A missed need whose words or price are on the page gets a hint to check the persona's pattern.
- A page or product card that leads to "Page not found" ends the journey as `broken_link`. A page that loaded without a recognisable photo is reloaded once.
- The report starts with one plain line ("it shopped like a customer up to the cart and stopped before checkout: it never tapped Checkout, never paid, never logged in, ..."), shows the detected platform, gives a suggested fix per item, and keeps the safety detail folded near the end.
- One policy for every request, in two guards: the request guard in each browser context and the Chromium browser-level guard (CDP `Fetch`), each checking every redirect hop with no fulfilled 3xx. Checkout, payment and login addresses (PrestaShop `controller=order`, WooCommerce `woocommerce_checkout`, BigCommerce `cart.php?action=buy`, Magento `payment-information` and `place-order` included) and payment hosts (Adyen, Braintree, Square, Authorize.net, Checkout.com, Mollie, Razorpay, Bolt, PayPal Fastlane, Shop Pay installments and more) are stopped; express buttons and pay-in-4 messages may not render. Shared endpoints carry only recognised cart operations, `--allow-host` covers static GET and HEAD only, every WebSocket is refused, and once the cart is touched page loads are held to the cart, the home page and the pages the cart was touched from. A checkout the page shows by itself (a hash route, `pushState`, an `about:blank` pop-up) ends the journey before the next tap, and one interaction policy refuses Checkout, express wallet, payment and login controls with no force.
- `npm run demo` writes to a temporary folder. Windows: `.gitattributes` keeps line endings plain, and every command has a PowerShell form. CI runs on Linux, Windows and macOS with Node 22 and 24.
